## Что проверено

Вход и пароли со значимыми пробелами; создание и обновление JWT в разных файлах; отзыв предыдущего токена; роли и чужие объекты; профиль; карточки; заявки; баллы и публикация; файлы и шаблоны; содержимое DOCX/XLSX; версии v1/v2 и локальная документация; реальные учебные данные и повторное заполнение.

Новые проверки: два SQL-запроса одновременно наблюдаются активными в pg_stat_activity; два входа проходят через синхронизированную проверку пароля в фоновых потоках; все HTTP-маршруты являются coroutine-функциями; фамилия, имя и отчество собираются внешней функцией; новые части ФИО принимаются API, неполные и противоречивые значения дают 422; недоступная БД даёт 503; внутренняя ошибка даёт 500 без раскрытия деталей.

## Единый стиль ошибок

Функции приложения используют try/except, регистрируют технический тип ошибки через log_error и передают исключение дальше. App/errors.py формирует один JSON-формат {"detail": ...}. Ошибки входных данных — 422, повторные записи — 409, отсутствие входа — 401, отсутствие прав — 403, недоступная БД — 503, непредвиденная ошибка — 500. Пароли, токены и SQL в ответ не включаются.

## Дефекты и ограничения

При переводе на async обнаружены неожидаемые coroutine-вызовы записи данных и служебного протокола. Добавлен await по цепочке вызовов; полный регрессионный набор успешен. Историческая ошибка вывода лишних внутренних полей psycopg также остаётся закрытой.

Проверка двух одновременных запросов подтверждает отсутствие соответствующей блокировки, но не заменяет нагрузочные испытания. Windows-команды подготовлены с выбором SelectorEventLoop, фактический запуск Windows и PostgreSQL 18 не проводился. Открытие файлов в Microsoft Office и длительная эксплуатация не проверялись. Полная история TDD не подтверждается. Django не входит в первый этап.
