# Установка и обслуживание этапа 7

Полная последовательность команд для Windows PowerShell и Linux/macOS приведена в [README этапа](../../README.md). Выполняйте их именно из stages/07_final_api. Базы: olympiads_stage07 и olympiads_stage07_test. Порядок: Python 3.12 → окружение → зависимости → SQL-настройка → configure.py → проверка тестовой БД → migrate → init_db --demo → Uvicorn.

SQL-настройка использует psql и \gexec. Её можно повторять: имеющиеся роль и базы не удаляются. Пароль существующей роли не меняется; укажите действующий пароль в .env. Миграция migrations/001_initial.sql выполняется через python -m app.migrate; повторное применение не пересоздаёт таблицы. Init_db вызывает ту же миграцию. Автоматический downgrade не предусмотрен.

PostgreSQL — обычная служба ОС. Docker не нужен. Установка Python в .venv не происходит: сначала установите Python 3.12, затем создайте окружение именно этой версией. На Windows не используйте просто py при создании окружения, если по умолчанию выбрана 3.14.

## Диагностика

При ошибке подключения проверьте службу, host/port, наличие роли и баз, пароль в обеих строках .env. При конфликте HTTP-порта используйте --port 8001 и соответствующий адрес документации. Scripts.smoke рассчитан на порт 8000.

На новой пустой базе --demo создаёт 111 пользователей, 50 олимпиад, 150 заявок и 200 DOCX. Повторный запуск сохраняет непустую базу. Хранилище storage должно сохраняться вместе с базой: в таблице attachments находятся имена файлов, сами документы лежат на диске.

## Резервная копия

Остановите API на время согласованного копирования. Создайте резервную копию своей базы pg_dump и скопируйте storage отдельно. Пример для команды psql в PATH:

```text
pg_dump -h localhost -U olympiad -d olympiads_stage07 -Fc -f olympiads_stage07.dump
```

Храните .env отдельно с ограниченными правами; не загружайте его в Git. Восстановление выполняется pg_restore в отдельную заранее созданную базу вместе с соответствующей копией storage. Восстановление из аварии и длительная работа в рамках этой проверки не испытывались.

Фактическая проверка выполнялась на Linux/PostgreSQL 17.11. Windows, PostgreSQL 18 и системный установщик отдельно не проверялись; рабочий компьютер студента требует собственного запуска команд README.
