# Учёт участия студентов в олимпиадах — этап 1, FastAPI

Курсовой проект Пеннер Андрея Владимировича. Основание — «Пеннер (1).pdf».
Срок первого этапа: **15 декабря 2026 года**. Второй этап (Django, до 1 мая 2027 года)
разрабатывается отдельно. Здесь реализован самостоятельный REST-сервис.

## Что реализовано

- Гость: список и карточки олимпиад, фильтр по году, опубликованные протоколы,
  положения и задания прошлых лет.
- Студент: вход, свой профиль, запись на несколько мероприятий, собственные
  заявки и результаты после публикации.
- Преподаватель: создание студентов со всеми полями ТЗ, документы своей олимпиады,
  результаты, подготовка и отзыв подготовленного протокола, Word/Excel,
  любое количество бланков сертификатов и грамот.
- Администратор: учетные записи, карточки олимпиад (CRUD), публикация,
  протоколы и годовой отчёт в DOCX/XLSX.
- JWT, PBKDF2 с солью, проверка ролей и принадлежности мероприятия.
- v1: обычный список. v2: список с пагинацией и поиском. Остальные правила одинаковы.
- PostgreSQL и SQLAlchemy. SQLite не используется даже в тестах.

Код состоит из обычных функций и небольших моделей. Дополнительный клиент
`client/` использует `requests.get/post/put/patch/delete`, как в презентации.

## Быстрый запуск

Нужны **Python 3.12** (поддерживаемая среда проекта), **Docker с Compose v2**,
свободные порты 5432 и 8000. Docker Desktop должен быть запущен.
Все команды выполняются **из корня проекта**.

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell вместо предыдущей строки:
# .venv\Scripts\Activate.ps1

python -m pip install -r requirements-lock.txt
python scripts/configure.py
docker compose up -d --wait
python scripts/create_test_db.py
python -m app.init_db --demo
python -m uvicorn app.main:app --reload
```

Если команда `python` недоступна в Linux, используйте `python3` при создании venv.
В PowerShell при запрете активации можно запускать `.venv\Scripts\python.exe` напрямую.
`requirements-lock.txt` фиксирует также транзитивные зависимости; `requirements.txt`
и `requirements-dev.txt` разделяют рабочие и тестовые инструменты.

Локальные адреса для запуска на своём компьютере:

| Назначение | Путь на сервере с портом 8000 |
|---|---|
| Проверка БД | `/health` |
| Swagger v1 / v2 | `/api/v1/docs`, `/api/v2/docs` |
| ReDoc v1 / v2 | `/api/v1/redoc`, `/api/v2/redoc` |
| OpenAPI | `/api/v1/openapi.json`, `/api/v2/openapi.json` |

Откройте в браузере адрес сервера с соответствующим путём. Swagger и ReDoc
используют локальные JS/CSS. Корневая `/docs` описывает только служебный маршрут;
для предметного API нужны страницы версий из таблицы.

### Демонстрационные аккаунты

| Роль | Логин | Учебный пароль |
|---|---|---|
| Администратор | `admin` | `Admin2026!` |
| Ответственный за олимпиаду №1 | `teacher1` | `Teacher2026!` |
| Другой преподаватель | `teacher2` | `Teacher2026!` |
| Студент | `student1` | `Student2026!` |

Всего исходно: **111 пользователей, 50 олимпиад, 150 заявок, 200 документов**.
Все данные вымышлены. Пароли намеренно известны для демонстрации; не используйте
такую базу для реальных персональных данных. JWT-ключ генерируется отдельно.
Повторный `--demo` не изменяет непустую базу. Проверка `scripts.smoke` добавляет
отдельный пример мероприятия и студента и сохраняет отчёты в локальную папку `reports/smoke/`.

### Вход в Swagger

Нажмите **Authorize**, введите логин и пароль. `client_id` и `client_secret`
оставьте пустыми. Можно также вызвать `POST /auth/token`: тип тела — форма,
поля `username`, `password`. Ответ содержит `access_token`.
В обычных запросах передавайте `Authorization: Bearer <access_token>`.
Токен действует 60 минут; выход и смена пароля отзывают все токены пользователя.

### Без демонстрационных данных

На **новой пустой БД** измените `ADMIN_PASSWORD` в `.env` и выполните
`python -m app.init_db` без `--demo`. Имя администратора — `ADMIN_USERNAME`.
Уже созданным аккаунтам это пароль не меняет: используйте API смены пароля.
Скрипт `configure.py` никогда не перезаписывает существующий `.env`.

## Проверка

```bash
# Быстрая проверка:
python -m pytest -q

# Подробные отчёты (локальные, в Git не попадают):
python -m pytest -q --cov=app --cov-report=term-missing --cov-report=html:reports/tests/coverage --cov-report=json:reports/tests/coverage.json --junitxml=reports/tests/junit.xml
python -m scripts.smoke
python -m client.main
```

Тесты используют только отдельную `TEST_DATABASE_URL`, имя БД должно оканчиваться
на `_test`. Изменения каждого теста откатываются. Рабочая база тестами не очищается.
Smoke-сценарий предназначен для учебных аккаунтов из `--demo` и запущенного сервера.
План, сценарии и результаты описаны в [документации тестирования](docs/testing/TESTING.md).
HTML-отчёт покрытия создаётся в `reports/tests/coverage/index.html`, результат
HTTP-проверки и четыре файла Word/Excel — в `reports/smoke/`.
Папка `reports/` исключена из Git.

## Правила предметной области

- Год олимпиады определяется по дате начала. Годовой отчёт содержит только
  опубликованные результаты; строка — одна запись участия, а не уникальный студент.
- Запись разрешена студентам до конца последнего дня мероприятия включительно,
  только при статусе `draft`. Повторная заявка возвращает 409.
- Статусы: `draft` (формируется), `prepared` (подготовлен), `published` (опубликован).
  Подготовка возможна в день окончания и позже, когда у всех участников есть баллы
  и результат. `prepared → draft` — отзыв. Из `published` возврата нет по ТЗ.
- Баллы: 0…999999.99, не более двух знаков после запятой.
  `winner` — победитель; `prize` — призёр; `participant` — участник.
  Преподаватель устанавливает результат по положению, система не придумывает пороги.
- Подготовленный/опубликованный протокол блокирует изменение баллов, заявок и карточки.
- Задания (`task`) доступны гостям только для мероприятий прошлых календарных лет.
  Ответственный видит список всех файлов в `/attachments/manage`.
- Документы: до 5 МБ, PDF/DOCX/XLSX/PNG/JPG/UTF-8 TXT. Имена в хранилище случайные.
  Для изменения файла используйте PUT с новым файлом и названием.
- Пустую олимпиаду можно удалить; при связанных заявках или документах возвращается 409.
- Самостоятельной публичной регистрации нет: студентов создают преподаватели,
  преподавателей — администратор. Это соответствует выданному ТЗ.

## Остановка и данные

Остановите Uvicorn сочетанием Ctrl+C. `docker compose stop` останавливает БД,
`docker compose up -d --wait` запускает её снова. Данные живут в Docker volume,
файлы — в `storage/`. Не используйте `docker compose down -v`: это удалит БД.
Для переноса нужны **и дамп PostgreSQL, и папка storage**, подробности — в [руководстве развёртывания](docs/guides/DEPLOYMENT.md).
В Git не входят `.env`, `.venv`, действующая БД и пользовательские файлы.
Демонстрационные данные воспроизводятся командой `--demo`.
