# Развёртывание и обслуживание

## Требования и каталоги

Проверенная среда: Python 3.12.14, PostgreSQL 17.11, Docker 28.4.0, Linux x86_64.
На Windows используйте Python 3.12 и Docker Desktop с контейнерами Linux.
Системная БД и файлы не встроены в приложение. Около 1 ГБ свободного диска
достаточно для учебного запуска; Docker-образ и venv требуют дополнительного места.

Команды установки приведены в README. После создания venv можно не активировать
его, а вызывать .venv/bin/python (Windows: .venv\Scripts\python.exe).
Команда docker compose up -d --wait ждёт успешной проверки pg_isready.
Если имя тестовой БД не оканчивается на _test, тестовый запуск блокируется.

## Настройки

| Переменная | Назначение |
|---|---|
| DATABASE_URL | Подключение SQLAlchemy с драйвером postgresql+psycopg |
| TEST_DATABASE_URL | Отдельная тестовая БД; суффикс _test обязателен |
| JWT_SECRET | Случайный ключ минимум 32 символа; configure.py создаёт 64 hex-символа |
| TOKEN_MINUTES | Срок действия токена, по умолчанию 60 |
| ADMIN_USERNAME / ADMIN_PASSWORD | Только создание первого администратора без --demo |
| STORAGE_DIR | Необязательная замена каталога storage |
| BASE_URL | Необязательный базовый адрес requests-клиента |

.env не публикуется в Git. Для паролей со специальными символами в URL требуется
URL-кодирование. Изменив PostgreSQL-пароль, согласованно исправьте DATABASE_URL
и TEST_DATABASE_URL. POSTGRES_PASSWORD и POSTGRES_DB в compose применяются только
к новому Docker volume, существующего пользователя они не меняют.

В Docker Compose порт БД привязан к 127.0.0.1, а не ко всем интерфейсам.
Подключение к внешней БД задаётся DATABASE_URL; PostgreSQL-контейнер тогда
не обязателен. Тестовой роли требуется доступ к отдельной тестовой БД.
create_test_db.py использует право CREATE DATABASE локального учебного пользователя;
на сервере без такого права администратор СУБД должен создать БД заранее.

## Контроль запуска

1. docker compose ps: база должна быть healthy.
2. python -m app.init_db --demo: первое создание схемы и данных.
3. python -m uvicorn app.main:app --reload: режим разработки.
4. GET /health: ожидается {"status":"ok","database":"postgresql"}.
5. GET /api/v1/olympiads: первоначально 50 записей.
6. POST /api/v1/auth/token: проверка входа, далее запрос профиля с Bearer-токеном.
7. python -m pytest -q: проверка отдельной тестовой БД.

create_all создаёт отсутствующие таблицы, но не мигрирует существующие.
Если в будущей работе изменится модель, потребуется отдельная миграция;
не удаляйте пользовательскую БД для применения изменений.

## Остановка и повторный старт

Ctrl+C останавливает Uvicorn. docker compose stop останавливает только БД,
volume сохраняется. Для возобновления выполните docker compose up -d --wait,
затем повторно запустите Uvicorn. Живые процессы не входят в переносимый архив.
Повторные configure.py и init_db --demo сохраняют имеющиеся настройки и записи.

## Резервное копирование

Остановите Uvicorn, чтобы новые загрузки и записи не нарушили согласованность копии.
Выполняйте команды из корня проекта. Указанный пользователь и имя базы — учебные;
при изменении настроек подставьте свои.

```bash
mkdir -p backup
docker compose exec -T db pg_dump -U olympiad -d olympiads -Fc > backup/olympiads.dump
python -c "import shutil; shutil.make_archive('backup/storage', 'zip', '.', 'storage')"
```

В PowerShell до 7.4 двоичное перенаправление может повредить дамп. Используйте:

```powershell
docker compose exec -T db pg_dump -U olympiad -d olympiads -Fc -f /tmp/olympiads.dump
docker compose cp db:/tmp/olympiads.dump backup/olympiads.dump
```

Храните копию .env отдельно с ограничением доступа. Для восстановления токенов
можно сохранить JWT_SECRET; для принудительного выхода всех пользователей
сгенерируйте новый ключ. Файлы storage содержат документы и также требуют защиты.

## Восстановление

Восстанавливайте в новую пустую базу, не поверх рабочей. Создайте её средствами
PostgreSQL, затем передайте дамп pg_restore. Например, при созданной olympiads_restore:

```bash
docker compose cp backup/olympiads.dump db:/tmp/olympiads.dump
docker compose exec -T db pg_restore -U olympiad -d olympiads_restore --no-owner /tmp/olympiads.dump
```

Распакуйте storage.zip во временный каталог, проверьте его содержимое и перенесите
storage в корень восстановленного проекта. Укажите новую БД в .env, запустите
сервер и проверьте профиль, список олимпиад и скачивание нескольких документов.
Не смешивайте дамп одной даты с файлами другой даты.

## Диагностика

- Порт 5432 занят: измените внешний порт Compose и обе строки подключения.
- БД не готова: docker compose logs db; pg_isready. Не отключайте проверки.
- Ошибка JWT_SECRET: запустите configure.py для новой .env или задайте случайный ключ
  в существующей .env. Скрипт существующий файл не перезапишет.
- Есть запись файла, но загрузка 404: восстановите соответствующий storage из копии.
- Нет учебных аккаунтов после --demo: база уже была непустой. Используйте имеющиеся
  аккаунты либо новую отдельную учебную БД, не очищая текущую автоматически.
- Библиотека не найдена: проверьте, что используется Python из .venv.

TLS, обратный прокси, аудит, распределённое хранилище, ограничение частоты входа
и полноценная эксплуатация с реальными персональными данными выходят за рамки
этого локального учебного развёртывания. Проверка нагрузки не проводилась.
