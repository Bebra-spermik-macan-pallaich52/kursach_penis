# План и отчёт тестирования первого этапа

## Паспорт

Проект: OLYMPIADS-REST, сборка 1.0.0. Тип отчёта: версионный, первый этап.
Дата контрольного прогона после уборки репозитория: 22.10.2026. Исполнитель автопрогона: среда разработки;
ФИО студента в проекте: Пеннер Андрей Владимирович. Ручная приёмка руководителем

## План

Цель — проверить операции ТЗ, валидацию и ограничения доступа. Основа — API-
и интеграционные тесты FastAPI TestClient + PostgreSQL. Параметризация проверяет
границы и неверные значения, без подмены БД на SQLite. Отдельный HTTP smoke
проверяет работающий Uvicorn и реальные бинарные выгрузки.

Начало: установлены зависимости, доступна отдельная БД, создана схема.
Завершение: все выбранные сценарии прошли, покрытие маршрутов и общих функций
не ниже 80%, нет необъяснённых падений, воспроизводится HTTP-сценарий.
Нагрузочное, полноценное security-тестирование и тесты Django не выполнялись.

Фикстуры: test_engine — подключение и схема тестовой БД; db — откатываемая
транзакция с savepoint; client — HTTP-клиент, подмена get_db у всех приложений
и временный файловый каталог; password_hash — подготовленный учебный хеш;
accounts — администратор, два преподавателя и два студента; headers — их JWT;
olympiad — мероприятие ответственного преподавателя на дату теста.
Пользовательские тестовые данные не смешиваются с демонстрационной рабочей БД.

Контрактные проверки tests/test_contract_first.py созданы до app.main.
Остальные сценарии
добавлялись в ходе реализации. Полная история каждого цикла red/green/refactor
не велась, поэтому строгий TDD всего проекта не заявляется задним числом.

## Итог

Контрольный прогон 22.10.2026: **75 тестов прошли**, падений и пропусков нет.
Покрытие строк app — **89.31%**,
модулей app/api — **99.27%** (406 из 409 строк).
CLI первоначального наполнения проверяется отдельно; это объясняет разницу
общего покрытия и покрытия маршрутов. Длительность прогона зависит от машины
и не является показателем производительности сервиса.

Подробные отчёты генерируются локально в исключённую из Git папку reports/:

```bash
python -m pytest -q --cov=app --cov-report=term-missing --cov-report=html:reports/tests/coverage --cov-report=json:reports/tests/coverage.json --junitxml=reports/tests/junit.xml
```

- reports/tests/coverage/index.html — HTML с покрытием по файлам.
- reports/tests/coverage.json — машинные метрики.
- reports/tests/junit.xml — результат для тестовых инструментов.
- reports/tests/pytest.txt — вывод текущего контрольного прогона в облачной среде;
  при самостоятельном запуске вывод виден в терминале.

Для проверки работающего сервера запустите python -m scripts.smoke с учебными
аккаунтами из --demo. Скрипт проверяет 13 шагов от входа до публикации и выгрузки.
Он сохраняет result.json, protocol.docx/xlsx и annual.docx/xlsx в reports/smoke/,
а в учебной БД оставляет отдельный вымышленный пример мероприятия и участника.
Контрольный HTTP-прогон 22.10.2026 завершён успешно: все 13 шагов выполнены,
четыре выгруженных файла повторно открыты как документы Word и книги Excel.

Первоначальное наполнение: 111 пользователей, 50 олимпиад, 150 заявок,
200 документов. Повторный --demo не изменяет непустую БД. Число записей после
HTTP-проверки увеличивается, поскольку её пример сохраняется.

Браузерная проверка Swagger v1/v2 и ReDoc выполнена при подготовке первого этапа
19.10.2026. Это проверка инструментов документации, а не Django UI.
Нагрузочные испытания и длительная устойчивость не проверялись.
