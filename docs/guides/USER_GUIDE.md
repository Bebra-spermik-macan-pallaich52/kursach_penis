# Руководство пользователя REST-сервиса

## Подготовка

Запустите сервер по [README](../../README.md). Для демонстрации используйте --demo. Основная рабочая
страница первого этапа — Swagger нужной версии, путь /api/v1/docs или /api/v2/docs.
Это интерфейс проверки сервиса; отдельный сайт Django будет во втором этапе.
Параметры в фигурных скобках заменяются реальными идентификаторами из ответов.

## Гость

1. Раскройте GET /olympiads, нажмите Try it out и Execute.
2. Для фильтра введите year=2025. Год определяется по startDate.
3. Передайте id из списка в GET /olympiads/{olympiad_id}.
4. Вызовите GET .../attachments. regulation — положение; task — прошлогодние
   задания; certificate/award — пустые бланки.
5. GET /attachments/{id} скачивает файл. При недоступном задании или удалённом
   файле получите 404; текущие задания не публикуются.
6. GET .../protocol показывает результаты, только если администратор опубликовал
   протокол. До этого 404 является ожидаемым ответом, а не ошибкой программы.

## Студент

1. Учётную запись выдаёт преподаватель. В Authorize введите student1 / Student2026!.
2. GET /users/me показывает профиль. PATCH /users/me принимает только изменяемые
   личные поля, например {"email":"student_new@example.org","course":4}.
3. Получите список олимпиад и найдите мероприятие со статусом draft, дата окончания
   которого ещё не прошла. POST .../participations не требует тела запроса.
4. Повторите для другой олимпиады. Повторная заявка на ту же вернёт 409.
5. GET /users/me/participations показывает все свои заявки. До публикации score
   и result равны null, после публикации содержат итоговые значения.
6. DELETE /participations/{id} отменяет свою заявку только при draft.
7. PUT /users/me/password меняет пароль. После операции войдите повторно.
8. DELETE /auth/session завершает все сеансы текущего пользователя.

## Преподаватель

1. Войдите как teacher1 / Teacher2026!. GET /protocols покажет только его олимпиады.
2. POST /users с role=student создаёт студента. Заполните fullName, birthDate,
   email, username, password, institution, educationLevel, course, specialty.
   Пример полного тела есть в [API.md](../api/API.md). Новый преподаватель этим способом
   не создаётся — операция вернёт 403.
3. Создайте положение через POST .../templates: kind=regulation, название и текст.
   Готовый файл можно прикрепить через POST .../attachments.
4. Для просмотра всех своих файлов, включая текущие задания, используйте
   GET .../attachments/manage. PUT /attachments/{id} заменяет файл и название.
5. GET .../participations показывает участников. PUT /participations/{id}/result
   сохраняет score и result. Возможные result: winner, prize, participant.
6. GET .../protocol-draft показывает протокол до публикации. Проверьте ФИО и баллы.
7. GET .../reports/protocol?format=docx или xlsx формирует Word/Excel. Незавершённый
   протокол содержит явный статус draft и прочерк вместо отсутствующих баллов.
8. PATCH .../protocol с {"status":"prepared"} готовит протокол. Окончание олимпиады
   должно наступить, все результаты должны быть заполнены.
9. Если нужны исправления, отправьте {"status":"draft"}, исправьте результаты
   и снова подготовьте протокол. После published отзыв запрещён.
10. Создавайте сколько нужно certificate и award: это отдельные записи файлов
    одной олимпиады. Бланк — заготовка, автоматического выпуска именных наград нет.

## Администратор

1. Войдите как admin / Admin2026!.
2. POST /users с role=teacher создаёт преподавателя; GET /users показывает аккаунты.
   PATCH /users/{id} меняет данные, password либо isActive. Роль через этот запрос
   не меняется. Блокировка аккаунта и смена пароля отзывают его токены.
3. Создайте карточку POST /olympiads: название, описание, teacherId, даты.
   PUT заменяет все поля карточки, PATCH — переданные поля. Удаление возможно
   только для draft без заявок и файлов.
4. Проверьте GET /protocols и служебный протокол. Публикуйте только проверенный
   prepared запросом PATCH .../protocol с {"status":"published"}.
5. После публикации проверьте протокол без авторизации.
6. Выгрузите годовой отчёт GET /reports/annual?year=2026&format=xlsx.
   Поддерживается и docx. Отчёт содержит только published, включая все участия
   одного студента в разных мероприятиях.

## Частые ответы

401 — войти снова; 403 — проверить роль и ответственного; 404 — проверить номер
и факт публикации; 409 — проверить статус, дубликат или связанные данные;
422 — исправить тело по подсказке detail; 413 — выбрать файл до 5 МБ.
Логин чувствителен к регистру. Тестовые почтовые адреса используют example.org.
